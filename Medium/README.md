## Common Patterns in Medium Problems

| Pattern | Description |
|---------|-------------|
| **Sliding Window** | Variable-size window, shrink/expand based on condition |
| **Two Pointers** | In-place array manipulation, pair/triplet finding |
| **Binary Search on Answer** | Search over the answer space, not just the array |
| **Hash Map + Complement** | O(n) lookups to replace O(n²) brute force |
| **Monotonic Stack** | Next greater/smaller element problems |
| **BFS / DFS** | Graph traversal, island problems, tree paths |
| **Dynamic Programming** | Overlapping subproblems, optimal substructure |
| **Backtracking** | Subsets, combinations, permutations |
| **Greedy** | Locally optimal choices leading to globally optimal solution |
| **Merge Intervals** | Sort + scan for overlapping ranges |

## Approach for Medium Problems

```
1. Read carefully — Medium problems often hide complexity in the description
2. State the brute force first — understand WHY it is too slow
3. Identify the pattern — what structure or technique applies?
4. Implement cleanly — Medium problems are the sweet spot for interview code
5. Trace through edge cases — off-by-one errors and empty inputs are common traps
6. Review complexity — aim for O(n) or O(n log n) where brute force is O(n²)
```
