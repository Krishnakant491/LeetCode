## Repository Structure

LeetHub organizes solutions at the **root level**, one folder per problem:

```
LeetCode/
├── {problem-number}-{problem-name}/
│   ├── {problem-number}-{problem-name}.java   ← solution file
│   └── README.md                              ← problem statement (auto-generated by LeetHub)
├── {problem-number}-{problem-name}/
│   ├── ...
└── readme.md                                  ← this file
```

**Real example from this repository:**

```
LeetCode/
├── 2267-check-if-there-is-a-valid-parentheses-string-path/
│   ├── 2267-check-if-there-is-a-valid-parentheses-string-path.java
│   └── README.md
└── readme.md
```

Every time a solution is accepted on LeetCode, LeetHub automatically:
1. Creates a folder named `{number}-{problem-name}/`
2. Commits the solution file (`.java`)
3. Commits the problem statement as `README.md`

## Problem-Solving Approach

A disciplined, repeatable workflow applied to every problem:

```
1. UNDERSTAND   →  Read carefully. Clarify what input/output is expected.
2. CONSTRAINTS  →  Identify size limits, edge cases, and implied constraints.
3. BRUTE FORCE  →  Think of the simplest correct solution first.
4. OPTIMIZE     →  Identify the bottleneck. Apply the right pattern or data structure.
5. IMPLEMENT    →  Write clean, readable code.
6. COMPLEXITY   →  Analyze time and space complexity explicitly.
7. TEST         →  Validate against provided examples and edge cases.
8. REFLECT      →  Review the solution pattern. Note what to remember.
```
